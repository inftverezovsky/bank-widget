# Bank Widget

Учебный проект для работы с банковскими операциями.

## Возможности

В проекте реализованы функции для:

- маскировки номера карты и счета;
- форматирования даты;
- фильтрации операций по статусу;
- сортировки операций по дате;
- последовательной выдачи транзакций и генерации номеров карт;
- чтения операций из JSON и конвертации USD/EUR в рубли;
- логирования вызовов функций, результатов и ошибок в консоль или файл.

## Установка

Требуется Python 3.12 или новее в пределах версии 3.x.

```bash
git clone https://github.com/inftverezovsky/bank-widget.git
cd bank-widget
git checkout feature/homework_logging
poetry install --with dev,lint
```

Команды ниже выполняются в виртуальном окружении проекта. Без его активации
добавьте перед командой `poetry run`, например `poetry run pytest`.

## Декоратор log

Модуль `src/decorators.py` содержит декоратор `log(filename=None)` для
синхронных функций. На каждый вызов записываются три сообщения:

1. `start` — имя функции, время вызова в UTC, позиционные и именованные аргументы;
2. `ok` и результат либо `error` с типом, текстом исключения и входными параметрами;
3. `end` — имя функции и время завершения в UTC, в том числе при исключении.

Без `filename`, а также при `filename=None`, сообщения выводятся в консоль:

```python
from src.decorators import log


@log()
def add_numbers(left: int, right: int) -> int:
    """Вернуть сумму двух чисел."""
    return left + right


result = add_numbers(1, 2)
assert result == 3
```

Пример вывода; временные метки зависят от момента вызова:

```text
add_numbers start. Time: 2026-09-15T10:00:00+00:00. Inputs: (1, 2), {}
add_numbers ok. Result: 3
add_numbers end. Time: 2026-09-15T10:00:00+00:00
```

Чтобы записывать сообщения в файл, передайте `filename`:

```python
from src.decorators import log


@log(filename="mylog.txt")
def divide(dividend: float, divisor: float) -> float:
    """Разделить одно число на другое."""
    return dividend / divisor


divide(6, 2)

try:
    divide(1, divisor=0)
except ZeroDivisionError:
    print("Деление на ноль: ошибка записана в mylog.txt")
```

Файл создается при первом вызове, сообщения дописываются в конец в UTF-8.
Каталог для файла должен существовать. Для ошибочного вызова в примере
записывается строка:

```text
divide error: ZeroDivisionError. Inputs: (1,), {'divisor': 0}. Error: 'division by zero'
```

После логирования исключение передается вызывающему коду без замены и подавления.
В логе сохраняются входные аргументы на момент начала вызова, даже если функция
изменила переданный список или словарь. Декоратор возвращает исходный результат,
сохраняет имя, docstring, аннотации и сигнатуру функции через `functools.wraps`,
`ParamSpec` и `TypeVar`.

Аргументы и результаты записываются без маскировки. Не передавайте в лог пароли,
токены или полные банковские реквизиты. К существующим функциям маскировки
декоратор автоматически не применяется. Ошибки записи файла также не подавляются.

## 12.1 — JSON и конвертация валют

`src.utils.load_transactions(path)` принимает строку или `Path` и возвращает список словарей. Отсутствующий, пустой, поврежденный или нечитаемый JSON, неверная кодировка, корневое значение не-список и список с элементами не-словарями дают `[]`. Корректные словари сохраняются без изменения. Исходный учебный файл — `data/operations.json`.

```python
from src.external_api import get_transaction_amount
from src.utils import load_transactions

operations = load_transactions("data/operations.json")
amount = get_transaction_amount({
    "operationAmount": {"amount": "123.45", "currency": {"code": "RUB"}}
})
```

`get_transaction_amount(transaction)` возвращает `float`: RUB — без сети, USD/EUR — через Exchange Rates Data API. Запрос использует параметры `from`, `to=RUB`, `amount`, заголовок `apikey` и таймаут 10 секунд. Неверная транзакция, неподдерживаемая валюта или отсутствующий ключ вызывают `ValueError`; сетевые ошибки и некорректный ответ API — `RuntimeError`, а не выдуманную нулевую сумму.

Для USD/EUR скопируйте `.env_template` в `.env` и задайте собственный `EXCHANGE_RATE_API_KEY`. `.env` исключен из Git; уже заданная переменная окружения имеет приоритет. Действующий ключ не включен в проект, поэтому сетевые сценарии проверены офлайн через `Mock` и `patch`, а не реальным запросом.

Логер `src.utils` пишет в `logs/utils.log` с уровнем DEBUG: успешные чтения — DEBUG, ошибки — ERROR. Формат содержит время, имя модуля, уровень и сообщение. Новый процесс перезаписывает журнал, повторный импорт не добавляет обработчики. Данные операций и секреты не записываются в журнал.

`src.generators` сохранен из предыдущей учебной ветки вместе с тестами: `filter_by_currency`, `transaction_descriptions`, `card_number_generator`. Файлы в `data/` предоставлены курсом и не являются выгрузкой личного банковского счета.

## 12.2 — Логирование

Модули `src.masks` и `src.utils` используют отдельные логеры уровня DEBUG и файловые обработчики. Журналы находятся в `logs/masks.log` и `logs/utils.log` относительно корня проекта. Формат записи содержит дату и время, имя модуля, уровень серьезности и сообщение.

Успешные вызовы фиксируются на DEBUG/INFO, ошибки — на ERROR с сохранением исходного поведения функций. Полные номера карт, счетов и API-ключи в журналы не записываются. При новом запуске процесса журнал перезаписывается; повторный импорт не дублирует обработчик и не стирает текущие записи. Файлы `.log` исключены из Git.

Тесты `tests/test_masks_logging.py` проверяют реальные файлы журналов в отдельных процессах, формат, успехи и ошибки, отсутствие реквизитов, перезапись и повторную загрузку модуля. Контракты функций маскирования из предыдущих заданий сохранены.

## Тестирование

Для тестирования используется `pytest`.

Запуск всех тестов:

```bash
pytest
```

Тесты разделены по модулям:

- `tests/test_masks.py` — функции из `masks.py`;
- `tests/test_widget.py` — функции из `widget.py`;
- `tests/test_processing.py` — функции из `processing.py`;
- `tests/test_decorators.py` — декоратор `log`;
- `tests/test_generators.py` — генераторы;
- `tests/test_utils.py` — чтение JSON и файловое логирование;
- `tests/test_external_api.py` — конвертация валют, включая ошибки API;
- `tests/conftest.py` — общие фикстуры с тестовыми данными.

В тестах используются фикстуры и параметризация `pytest.mark.parametrize`.
Вывод в консоль проверяется через `capsys`, файлы создаются во временной
директории `tmp_path`. Для декоратора проверяются оба назначения логов,
успех и исключения, передача аргументов, временные метки, дозапись,
кириллица, сохранение результата и метаданных, независимость функций.
Дополнительно проверяются ошибки открытия файла, относительные пути,
порядок записей, исходные аргументы и следующий вызов после исключения.

Покрытие строк и ветвлений запускается автоматически вместе с `pytest`.
Минимально допустимое покрытие в настройках проекта — 80%.

Полный отчет `coverage.py` для исходников этой ветки сохранен в `htmlcov/`.
Откройте `htmlcov/index.html` в браузере. Команда `pytest` пересоздает отчет;
актуальный результат автоматической проверки также доступен в GitHub Actions.

## Проверка качества кода

```bash
flake8 src tests
mypy src tests
isort --check-only --diff src tests
```

Зависимости описаны в `pyproject.toml` и зафиксированы в `poetry.lock`.
GitHub Actions устанавливает проект и инструменты проверки из совместимых диапазонов.
Проверки запускаются для feature-веток и pull request в `develop`.
Отдельно проверяется, что игнорируемые файлы не отслеживаются Git.

## Именование и Git

Имена переменных и функций записаны в `snake_case`. Декоратор и его вложенные
функции имеют docstring с описанием параметров и результата; возможные
исключения описаны там, где они возникают.

Файлы логов `*.log`, пример `mylog.txt`, `.coverage` и кеши не добавляются
в репозиторий. HTML-отчет хранится по условию задания; его служебный
`status.json` исключен через `htmlcov/.gitignore`.

Ветка этой домашней работы — `feature/homework_logging`, целевая ветка PR —
`develop`. Предыдущие pull request не изменяются; принятый код генераторов сохранен в новой ветке.
